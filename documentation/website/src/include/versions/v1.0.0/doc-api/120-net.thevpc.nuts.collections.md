# Package net.thevpc.nuts.collections

<a id="pkg-net-thevpc-nuts-collections"></a>

Collection abstractions and utilities not provided directly by the JDK.



It includes primitive lists and queues, evicting and capped collections,
observable collections and listeners, multivalue and indexed maps, collection
diffs, builders, and persistent/chunked stores.

## NBPlusTree

```java
public interface NBPlusTree<K, V> extends Map<K,V>, AutoCloseable
```

A self-balancing B+ Tree implementation that extends `Map`.



This collection is optimized for high-performance retrieval, insert, and delete operations.
It supports both in-memory usage (using standard Java object references) and page-based/file-based
persistence layouts. It can also configured to either act as a unique-key map or support duplicate keys.



**Author:** vpc

**Since:** 0.8.4

## NCappedMap

```java
@NSince("0.8.9")
@NRenamed(value = "NLRUMap", since = "1.0.0")
public interface NCappedMap<K, V> extends Map<K,V>
```

**Since:** 0.8.9

> [!NOTE]
> **Renamed:** previously `NLRUMap` (since 1.0.0)

A `Map` that is limited to a maximum number of entries.



When the map reaches its capacity, further insertions cause entries to be
evicted according to the concrete implementation’s policy
(for example LRU, LFU, FIFO, etc.).



The capacity can be changed at runtime via [#resize(int)](#m-resize).
Reducing the capacity may trigger immediate eviction of excess entries.





### Method Summary

| Modifier and Type | Method | Description |
| :--- | :--- | :--- |
| `void` | [resize(int)](#m-NCappedMap-resize) | Sets the maximum number of entries this map may hold. |
| `int` | [maxEntries()](#m-NCappedMap-maxEntries) | Returns the current maximum number of entries |

<a id="cls-net-thevpc-nuts-collections-NChunkedStore"></a>

## NChunkedStore

```java
public interface NChunkedStore<T> extends AutoCloseable
```

A generic, chunk-based persistence store for elements of type `T`.



The `NChunkedStore` partitions and stores objects in multiple consecutive chunk files
within a designated folder on the filesystem. This is useful for dealing with datasets
or queues that exceed the available system memory by flushing/paging elements to disk.





Implementations typically buffer incoming records in memory and flush them to the current chunk
file on disk once the buffer size limit is exceeded, or when a new chunk is started.



**Since:** 0.8.4

### Method Summary

| Modifier and Type | Method | Description |
| :--- | :--- | :--- |
| `void` | [flush()](#m-NChunkedStore-flush) | Flushes any currently buffered, in-memory elements to the active chunk file on disk. |
| `void` | [add(T)](#m-NChunkedStore-add) | Adds the specified element to the store. |
| `boolean` | [isEmpty()](#m-NChunkedStore-isEmpty) | Checks whether the store is empty. |
| `long` | [size()](#m-NChunkedStore-size) | Returns the total number of elements currently stored in this chunked store. |
| `NIterator&lt;T&gt;` | [iterator()](#m-NChunkedStore-iterator) | Returns an iterator over all elements in the store. |
| `NStream&lt;T&gt;` | [stream()](#m-NChunkedStore-stream) | Returns a sequential stream of elements from the store. |
| `void` | [close()](#m-NChunkedStore-close) | Closes this store, flushing any remaining buffered elements to disk. |
