<a id="m-NMavenSettingsLoaderBoot-isProfileActive"></a>

#### isProfileActive

```java
private boolean isProfileActive(Element profile, String profileId, Set<String> requestedProfiles)
```

Maven activates a profile when it is requested through
`<activeProfiles>`, or when it declares
`<activeByDefault>true</activeByDefault>`. Any other activation
condition (`jdk`, `os`, `property`, `file`) is not
evaluated, so such a profile is left inactive rather than being wrongly
assumed to apply.

**Parameters:**

- `profile` - profile element
- `profileId` - profile id
- `requestedProfiles` - ids listed in `<activeProfiles>`

**Returns:**

true if the profile must be considered

<a id="m-NReservedMavenUtilsBoot-isLocalMavenExcluded"></a>

#### isLocalMavenExcluded

```java
private static boolean isLocalMavenExcluded(NBootOptionsInfo options)
```

Whether the local maven repository (`maven-local`) must be skipped
while resolving boot artifacts. This is requested either by
`--local-maven=false` or by an explicit `--repos=-maven-local`
selection. Only the local repository is dropped: central and the settings
repositories remain usable, so excluding the sub-repository never makes
the runtime unloadable.

**Parameters:**

- `options` - current boot options

**Returns:**

true if the local maven repository must not be consulted
