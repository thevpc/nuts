## NApp

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface NApp
```

Marks a class as the definition of a Nuts application.



The annotated class typically contains lifecycle methods annotated with
[NAppInstall](#cls-NAppInstall), [NAppUninstall](#cls-NAppUninstall), [NAppUpdate](#cls-NAppUpdate),
and [NAppRun](#cls-NAppRun), which define the installation, uninstallation,
update, and execution behaviors of the application.






The optional `id` attribute allows specifying a unique identifier
for the application. If left empty, the framework may generate an
identifier based on the class name or other metadata.







Example usage:
```java
@NApp(id = "com.example.myapp")
public class MyApp {
    @NAppInstall
    public static void install() { ...

    @NAppRun
    public static void run() { ... }
}
}
```

## NAppComplete

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NAppComplete
```

Marks a method as an application complete entry point.



Methods annotated with `@NAppComplete` are intended to perform ...

```java
@NApp
public class AppMain {

    public static void main(String[] args) {
        NApplication.builder(args).run();

    // ... installer/updater/uninstaller unchanged ...

    @NAppRun
    public void run() {
        AppOptions o = processCmdLine(NApplication.of().cmdLine());
        //.... do run the application
    }

    @NAppComplete
    public void complete() {
        NCmdLine cmdLine = NApplication.of().cmdLine();
        processCmdLine(cmdLine);
        cmdLine.printCompleteResult();
    }

     // Single walk, shared by exec and completion.
    private AppOptions processCmdLine(NCmdLine cmdLine) {
        AppOptions o = new AppOptions();

        while (cmdLine.hasNext()) {
            if (cmdLine.next(cmdLine.createMatcher()
                    .whenOption("-i", "--interactive")
                    .as(NArgName.of("interactive"))
                    .matches()) != null) {
                o.setInteractive(true);
                continue;
            }

            if (cmdLine.next(cmdLine.createMatcher()
                    .whenOption("-c", "--command")
                    .as(NArgName.of("command"))
                    .requireValue()
                    .matches()) != null) {
                o.setCommand(cmdLine.nextString().get());
                continue;
            }

            if (cmdLine.isNextNonOption()) {
                o.getScripts().add(cmdLine.nextString().get());
                continue;
            }

            cmdLine.throwUnexpectedArgument();
        }

        return o;
    }
}

}
```

## NAppInstall

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NAppInstall
```

Marks a method as the installer for an application.



Methods annotated with `@NAppInstall` are responsible for
performing installation tasks, such as setting up required resources,
directories, or configuration needed before the application can run.






Typically, the annotated method should be public and static. It may
optionally take parameters that provide context about the installation
environment or workspace.







Example usage:
```java
public class MyApp {
    @NAppInstall
    public static void install() {
        System.out.println("Installing application resources...");
}
}
```




**Author:** thevpc

**Since:** 0.5.4

## NAppRun

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NAppRun
```

Marks a method as the main application entry point to be executed.



Methods annotated with `@NAppRun` serve as the primary runtime
entry for the application logic. This is the method that will be invoked
when the application is started through the Nuts framework.






Typically, the annotated method should be public and static, and can
accept arguments as needed for execution. The framework detects this
annotation to automatically invoke the method as part of the application
lifecycle.







Common usage:
```java
public class MyApp {
    @NAppRun
    public static void main(String[] args) {
        System.out.println("Application started!");
}
}
```




**Author:** thevpc

**Since:** 0.8.7

## NAppUninstall

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NAppUninstall
```

Marks a method as an application uninstaller entry point.



Methods annotated with `@NAppUninstall` are intended to perform
clean-up or removal operations for the application, such as deleting
installed files, unregistering resources, or reversing changes applied
during installation.






Typically, the framework or runtime will detect and invoke these methods
when an uninstallation process is triggered. The annotated method should
be public, and static if required by the framework, and should handle
the uninstallation logic safely.




**Author:** thevpc

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface NAppUpdate
```

Marks a method as an application updater entry point.



Methods annotated with `@NAppUpdate` are intended to perform
update operations for the application, such as downloading new versions,
applying patches, or refreshing internal resources.






Typically, the framework or runtime will detect and invoke these methods
when an update process is triggered. The annotated method should be
public, static (if required by the framework), and accept the expected
parameters defined by the update mechanism.

## NApplicationBuilder

```java
public class NApplicationBuilder
```

Builder used to configure and execute a Nuts [NApplicationHandler](#cls-NApplicationHandler).



This class supports:


- Automatic discovery of the application class (from `main()` when applicable)
- Explicit instance injection via [#instance(Object)](#m-instance)
- Reflective construction via [#type(Class)](#m-type)
- Control of error-handling mode (handle, propagate, exit, ignore)
- Providing both Nuts arguments and application arguments



<h2>Basic Usage</h2>



A typical JVM application may delegate to Nuts as follows:

```java
public static void main(String[] args) {
    NApplication.builder(args).run();
}
```

<h2>Advanced Custom Instance Construction</h2>



If you want the builder to instantiate your application class reflectively:

```java
NApplication.builder(args)
    .type(MyApplication.class)
    .handleErrors()
    .run();
```

<h2>Error Handling</h2>



The handling strategy is selected via:


- [#handleErrors()](#m-handleErrors)      – default Nuts behavior
- [#propagateErrors()](#m-propagateErrors)   – rethrow exceptions to caller
- [#fatalErrors()](#m-fatalErrors)       – exit the JVM on error
- [#ignoreErrors()](#m-ignoreErrors)      – ignore exceptions





This builder orchestrates argument parsing, instance preparation, execution mode
dispatching, and high-level runtime behavior for Nuts applications.

<a id="cls-net-thevpc-nuts-app-NApplicationHandler"></a>

## NApplicationHandler

```java
public interface NApplicationHandler
```

Nuts Application is the Top Level interface to be managed by nuts. By default, NApplication classes :


- have a nutsApplication=true in their descriptor file (in maven descriptor you should add a property nuts.application=true)
- support inheritance of all workspace options (from caller nuts process)
- enables auto-complete mode to help forecasting the next token in the command line
- enables install mode to be executed when the jar is installed in nuts repos
- enables uninstall mode to be executed when the jar is uninstalled from nuts repos
- enables update mode to be executed when the a new version of the same jar has been installed
- have many default options enabled (such as --help, --version, --json,--table, etc.) and thus support natively multi output channels
- have a well defined storage layout (with temp, lib, config folders, etc...)


Typically, a Nuts Application follows this code pattern :
```java
package org.example.test;

import net.thevpc.nuts.app.NApplication;
import net.thevpc.nuts.core.NSession;
import net.thevpc.nuts.cmdline.NArg;
import net.thevpc.nuts.cmdline.NCmdLine;
import net.thevpc.nuts.cmdline.NCmdLineContext;
import net.thevpc.nuts.cmdline.NCmdLineRunner;

import java.util.ArrayList;
import java.util.List;

public class MyApplication1 implements NApplication {
    public static void main(String[] args) {
        // just create an instance and call runAndExit in the main method
        new MyApplication1().run(NAppRunOptions.ofExit(args));
    }

    public void run() {
        session.runAppCmdLine(new NCmdLineRunner() {
            boolean noMoreOptions = false;
            boolean clean = false;
            List<String> params = new ArrayList<>();

            public boolean nextOption(NArg option, NCmdLine cmdLine, NCmdLineContext context) {
                if (!noMoreOptions) {
                    return false;
                }
                switch (option.key()) {
                    case "-c":
                    case "--clean": {
                        NArg a = cmdLine.nextFlag().get();
                        if (a.isEnabled()) {
                            clean = a.getBooleanValue().get();
                        }
                        return true;
                    }
                }
                return false;
            }

            public boolean nextNonOption(NArg nonOption, NCmdLine cmdLine, NCmdLineContext context) {
                params.add(cmdLine.next().get().toString());
                return true;
            }

            public void onCmdExec(NCmdLine cmdLine, NCmdLineContext context) {
                if(clean){
                    cmdLine.getSession().out().println("cleaned!");
                }
            }
        });
    }
}
