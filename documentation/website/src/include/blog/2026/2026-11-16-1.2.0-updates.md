## Changes

Nuts 1.2.0.0 started on 2026-11-18

## Changes Details
-  2026-11-21 : ARCH-08 slice 1: split `TsonCustomLexer` (~2,380 → ~880 lines) into package-private `TsonStringLexer` and `TsonNumberLexer` helpers behind the unchanged public facade. `TsonLexerCharacterizationTest` locks the exact token stream for a 19-case corpus so the refactor cannot change lexer behavior
-  2026-11-21 : closed the segmented-download integrity gap: `NSegmentedHttpDownload.Options.expectedChecksum` now verifies both ranged and sequential downloads, deletes files that fail verification, and is covered by two new `SegmentedDownloadTest` cases (callers still need to supply per-resource checksum metadata)
-  2026-11-21 : synchronized the source and generated `CONTRIBUTING.md`: documented the Java 8–25 CI matrix, the `local-only` test tag and the `test/nuts-runtime-test` test lane. `DocumentationConsistencyTest` guards the alignment
-  2026-11-21 : removed the stale per-module `licenseheader.txt` templates and documented that the root `LICENSE` is the single licensing source in `CONTRIBUTING.md`. `LicenseTemplateTest` guards the cleanup
-  2026-11-21 : removed the unused `runtime/deprecated` helper stack (and its JPMS export). `DuplicateImplementationTest` now keeps both live zip paths on the shared `resolveSafeEntry` guard and documents why the legacy V1 and new V2 secret codecs must both remain
-  2026-11-21 : added an architectural guard for the runtime package graph. Existing bidirectional package dependencies are snapshotted, and `PackageCycleGuardTest` fails the build if a new cycle is introduced (removing cycles remains always allowed)
-  2026-11-21 : deleted 33 fully commented-out Java sources (~3,200 lines) from the runtime module. `NoDeadSourceFilesTest` prevents them from creeping back in
-  2026-11-21 : added lifecycle reset hooks for static caches (`NIdClassLoaderRegistry.resetForTests()`, `NWorkspaceProfilerImpl.resetForTests()`) so embedding applications and tests can recreate workspaces in one JVM without leaking classloaders or profiling data. `StaticCacheLifecycleTest` covers two-workspace recreation
-  2026-11-21 : cleaned up the Maven build: javadoc now runs at `package` instead of `compile`, the obsolete Java 8 javadoc toolchain requirement was removed, the antrun plugin version is pinned in `parent/pom.xml`, and the JDK 9+ "obsolete source/target options" warning is suppressed. `BuildVersionConsistencyTest` verifies the settings
-  2026-11-21 : removed stale JavaCC leftovers (the hardcoded `run-javacc` script, machine-specific `compare-with-tson.txt`, and both unused `.jj` grammars); the hand-written TSON lexer remains the only parser. `StaleAssetsTest` guards the cleanup
-  2026-11-21 : removed mixed hardcoded versions. `nuts.api.version` and `nuts.impl.version` in `parent/pom.xml` are now the single source of truth for all `net.thevpc.nuts` dependency versions, and a consistency test checks them against `NBootWorkspace.NUTS_BOOT_VERSION` / `DefaultNWorkspace.RUNTIME_VERSION` (`BuildVersionConsistencyTest`)
-  2026-11-21 : made the optional Windows libraries truly optional. `OptionalJansi` and `OptionalMsLinkHelper` no longer contain direct bytecode references to `org.fusesource.jansi` / `mslinks`, so the wrappers (and their availability checks) work when those libraries are not deployed; the dead `window=false` install branch was removed. Regression test in `OptionalDependencyTest`
-  2026-11-21 : made JPMS/module-path launches work and fixed the multi-release JAR. The runtime descriptor now exports runtime packages, declares `uses`/`provides` for workspace discovery (boot factory plus 150 `NComponent` providers), and internal API RPI packages are exported only to the runtime module. A duplicate `NComponent` service entry was removed. `module-info.class` is placed under `META-INF/versions/9` at package time instead of the JAR root; `jar --describe-module --release 9` and a real module-path smoke test (`JpmsSmokeTest`) verify provider discovery and descriptor layout
-  2026-11-20 : improved hot-path performance: HTTP responses now keep connections alive instead of disconnecting after every read, cheap ranged GETs replace full-body existence probes, JAXP/XML/StAX factories and date formatters are reused per thread, regexes and record metadata are cached, folded YAML is linear instead of quadratic, and CFORMAT `%s` avoids allocating a `Formatter`. Also fixed boot deployment re-fetching the same artifact for every dependency. Regression tests in `PerformanceRegressionTest`
-  2026-11-20 : hardened security-sensitive paths: basic auth encoding now always uses UTF-8, integrity/equality digests use SHA-256, type resolution no longer runs static initializers for caller-supplied names and validates class names, process-builder diagnostics redact URLs and non-allowlisted environment values, and the authentication-agent passphrase can be supplied via `NUTS_AUTHENTICATION_AGENT_PASSPHRASE`. Legacy V1 secrets remain readable for migration and V2 remains the default for new secrets. Regression tests in `SecurityHardeningTest`
-  2026-11-20 : fixed the P2 correctness batch: rejected cached values are now recomputed instead of returned, shell/fish highlighter word lookahead uses the next token, TSON `<` operator tokens carry consistent images/variants, the runtime-dependencies setter actually persists changes, and malformed/placeholder-mismatched diagnostic messages were corrected. Regression tests in `P2CorrectnessTest`
-  2026-11-20 : made authentication caches thread-safe. Parallel download/solver threads now share a single `ConcurrentHashMap`-backed authentication-agent cache, authorization entries use a concurrent map, and the Maven client's bootstrap state uses an atomic state machine instead of a racy field. Regression test in `ConcurrencyReliabilityTest`
-  2026-11-20 : made configuration writes atomic. JSON and string config files are written to a sibling temporary file, fsynced, then atomically moved into place; a failed write leaves the previous config intact and cleans up temporary files. Regression tests in `AtomicConfigWriteTest`
-  2026-11-20 : fixed process execution reliability. PID discovery now uses the public `Process.pid()` API where available, PATH redirects write to the correct stream variables, GRAB_FILE redirect cases no longer fall through, and PATCH no longer silently downgrades to POST when JDK internals are unavailable. Regression tests in `ProcessExecutionReliabilityTest`
-  2026-11-20 : fixed file-descriptor and HTTP connection leaks. Directory digest streams are now closed, closing a partially read download never throws and is null-safe, and HTTP connections are disconnected on error paths before a response body is handed off. Regression tests in `ReliabilityLeakTest`
-  2026-11-20 : fixed P1 correctness bugs: classpath scanning no longer stops at the first unloadable class, `--main-class Foo` now registers `Foo` (not the option name), legacy secret decryption is UTF-8-safe on every platform, and truncated ciphertext is rejected with bounds checks. Regression tests in `P1CorrectnessTest`
-  2026-11-20 : made the test suite hermetic for CI. Tests that depend on maintainer machines or external extensions (`SshTest`, `UncompressTest`, SSH-based `PsTest` cases, and the network-dependent old-workspace migration test) are now tagged `local-only`, and local command scripts no longer hardcode absolute repository paths. CI full suite now excludes them consistently
-  2026-11-20 : improved effective-descriptor resolution performance. Source fingerprints are memoized (bounded, validated against descriptor content and parent ids), and standard-dependency lookup is now an indexed map rather than an O(n·m) rescan. Regression tests in `DescriptorCachePerformanceTest`
-  2026-11-20 : added integrity verification for downloaded JDK/tool archives. Metadata checksums (SHA-256, or legacy SHA-1) are now verified before an archive is extracted or executed, and downloads without a usable checksum are rejected. Regression tests in `DownloadIntegrityTest`
-  2026-11-20 : fixed credential leakage in repository URLs and logs. URL userinfo and `ul`/`up` (plus `password`, `token`, `secret`, `api-key`) query parameters and `Authorization` headers are now centrally redacted from logs and exceptions; Basic auth derived from inline URL credentials is HTTPS-only and UTF-8-safe, cleartext HTTP inline credentials are stripped, and percent-escaped/`+`/colonless userinfo is decoded correctly. Documented HTTPS inline URL auth remains supported. Regression tests in `CredentialSecurityTest`
-  2026-11-20 : fixed service-name command injection. Service names are now validated against a strict safe-character pattern before they are used in root installation/uninstallation scripts and service unit files, every value interpolated into those scripts is shell-quoted, and newline injection into unit-file variables is rejected. Regression tests in `ServiceCommandSecurityTest`
-  2026-11-20 : fixed secure-mode password verification. Enabling or disabling secure mode now validates the candidate against the stored admin credential (using the configured authentication agent) instead of comparing a hash with the password itself, which previously allowed any password to disable secure mode and prevented enabling it with a valid one. Regression test in `SecurityModeTest`
-  2026-11-20 : fixed four P0 correctness issues: repository authentication lookup no longer dereferences a missing repository object (and now tolerates empty access lists), CLI variable `saveVar` now actually persists changed values, in-memory `CachedSupplier` now reuses values while the cache id is valid (it was recomputing on every read), and `NSession --progress` now uses the parsed argument and applies the option exactly once. Regression tests in `P0CorrectnessTest`
-  2026-11-20 : hardened archive extraction. ZIP/ZIP-installer entries are now validated against the extraction root (no `../`, absolute paths, Windows drive/UNC forms or symlink crossings), archive expansion is bounded by configurable budgets (`nuts.archive.max-total-bytes`, `nuts.archive.max-entry-bytes`, `nuts.archive.max-entries`, `nuts.archive.max-compression-ratio`) and partially extracted files are removed on failure. Workspace backup restore now sanitizes workspace names read from the archive, and a leaked `FileInputStream` when adding files to ZIPs was fixed. Regression tests in `ArchiveSecurityTest`
-  2026-11-19 : fixed `NCompress` with stream targets (`to(OutputStream)`): `NCompressZip` and `NCompressGzip` only accepted path targets and failed with `unsupported target`. Any `NOutputTarget` is now accepted, with a uniform rule: whoever calls `NOutputTarget.outputStream()` closes it, so a caller that must keep its stream open passes it wrapped in `NonClosableOutputStream`
-  2026-11-19 : fixed applications always exiting with code 0 on error: `NApplicationBuilder.run()` in the default `NApplicationHandleMode.HANDLE` printed the error then returned normally. It now keeps the exit code: when the application owns the JVM (no workspace in scope) it exits with it; when run in-process by a host workspace (embedded, `-b`) it rethrows so the host gets the code (no `System.exit` there)
-  2026-11-19 : fixed `JavaExecutorComponent` (embedded execution) rewrapping an application's `NExecutionException` with the default code 255, losing the application's exit code
-  2026-11-19 : fixed TSON lexer (`TsonCustomLexer`) token text of `=`-suffixed operators: `!=`, `+=`, `-=`, `~=`, `*=`... (and their `==` forms) were built as `!!`, `++`, ... so `a != b` was re-read as `NOperatorSymbol.NOT2`
-  2026-11-19 : fixed TSON lexer (`TsonCustomLexer`) fallback operator branch: single-char/unicode operators (e.g. `|`, `∀`) produced a token whose text was the code point number (`"124"`, failing with `NOperatorSymbol invalid value : 124`) and the character was never consumed; surrogate pairs are now peeked and consumed together
-  2026-11-19 : added TSON lexing of `|`, `||`, `|||` as `NOperatorSymbol.PIPE` / `PIPE2` / `PIPE3` (previously split into single `|` tokens); regression tests in `TsonParseTest`
-  2026-11-19 : fixed TSON lexer (`TsonCustomLexer`) splitting `->` and `-->` into separate `-` / `>` tokens; they are now emitted as `NOperatorSymbol.MINUS_GT` / `NOperatorSymbol.MINUS2_GT`, so `NFlatExprElement.reshape()` of ranges like `[1 -> 5]` yields a binary expression instead of a diagnostic
-  2026-11-18 : Support authenticated private Maven repositories (credentials configuration and inline URL auth for Reposilite, Gitea, Forgejo, etc.)
-  2026-11-18 : Nuts 1.2.0.0 started
