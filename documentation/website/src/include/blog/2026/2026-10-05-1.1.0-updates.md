## Changes


## Changes Details
- 2026-11-06 : added `NSearch::dependsOn` / `NSearch::addDependsOn` / `NSearch::clearDependsOn`, the `--depends-on=<id>` search option and `NDefinitionFilter::ofDependsOn(NId|String)` : select artifacts that depend, directly or transitively, on a given artifact whose resolved version (maven mediation : nearest wins, root `dependencyManagement` and exclusions applied) matches the version filter, e.g. `nuts search --latest --depends-on='net.thevpc.ntexup:ntexup-api#[1.1,1.2[' net.thevpc.ntexup:ntexup-extension-shapes2d`. Resolution (`NDependsOnResolver`) walks descriptors only, breadth first, and stops at the first occurrence; an artifact may declare the result itself with the `nuts.depends.<groupId>.<artifactId>` descriptor property; results are cached in memory and, for released versions, under the workspace cache (`depends-on/`), refreshed by `-N`/`--expire`. Within `NSearch`, depends-on constraints are kept out of the repository-level filter : with `--latest` versions are evaluated newest first and the search stops at the first match (latest matching version, instead of resolving every version then keeping the latest)
- 2026-11-06 : changed `NSearch::targetApiVersion` / `--api-version` (without an exec type) and `NDefinitionFilter::ofApiVersion` to be `dependsOn(net.thevpc.nuts:nuts#<version>)`; removed `NutsAPIDefinitionFilter`, which ran a full transitive `NFetch` for every candidate version
- 2026-11-06 : fixed `NDefinitionExecExtensionFilter`, `NDefinitionExecRuntimeFilter` and `NDefinitionExecCompanionFilter` throwing `NullPointerException` when built without an api version (`byExtension(null)`, ...)
- 2026-11-06 : fixed AWT/Swing being loaded on every workspace boot (~200 `java.desktop` classes, even for `nuts version`) : `NDependencyFilters::byCurrentDesktop` (used by the runnable filter of the boot class loader) is now lazy (`NDependencyCurrentDEFilter`, the desktop is only detected when a dependency declares a desktop condition), `NSysExecUtils::buildEffectiveCommandLocal` no longer resolves `NEnv::desktopEnvironmentFamilies` for plain (non run-as) commands, and `NEnvLocal` no longer probes the graphical environment eagerly in its initialization
- 2026-11-06 : fixed `NEnvLocal::isGraphicalDesktopEnvironment0` returning `false` when called before any other `NEnvLocal` getter (its `gui` field shadowed the `NEnvBase` one and was only set by `init()`), and `NEnvLocal::getShell0` returning `null` under the same condition
- 2026-11-06 : fixed `NEnvLocal` initialization publishing `initialized = true` before the os/shell/user fields were set, so another thread could read them as `null`; initialization is now synchronized, with a re-entrance guard for the shell probe that runs `NExec`
- 2026-11-06 : fixed posix shell version detection in `NEnvLocal` : the version was read from `$BASH_VERSION`/`$ZSH_VERSION` inside `sh -c`, which describes `sh` and not the user `$SHELL` (zsh users got bash's version, dash systems got none); the probed `$SHELL --version` line is now used when it does not confirm that value
- 2026-11-06 : fixed `URLPath` header cache and `URLPath::equals`/`hashCode` being keyed by `java.net.URL`, whose `equals`/`hashCode` perform a blocking DNS lookup; they now use the url external form, and the shared access-ordered LRU cache is synchronized (concurrent `get` could corrupt it)
- 2026-11-06 : fixed unsynchronized shared static caches : `NLogUtils` (level, verb and class name caches), `NElementMapperEnum` lenient parsers (concurrent `HashMap::computeIfAbsent` may throw `ConcurrentModificationException`), `NHomeLocation` and `NMsgIntent` (read outside their lock) now use `ConcurrentHashMap`
- 2026-11-06 : fixed `NMetaInfIdResolver::resolvePomVersion` leaking the `pom.properties` stream (keeps jar files open, locked on Windows)
- 2026-11-06 : fixed slow workspace boot : `MavenSettingsRepository` probed `<url>/.nuts-repository` (HEAD + GET, with TLS setup) for every extra `~/.m2/settings.xml` repository on every boot, even for `nuts version`, and could block up to the 30s connect timeout when the network silently drops packets. The probe result is now cached under the workspace cache (`maven-settings/*.nuts-repository`) for 24h, refreshed by `-N`/`--expire`, and never probed when `--offline` (warm `version` : ~2.6s -> ~0.5s)
- 2026-11-06 : fixed `-N`/`--expire` stale-artifact refresh in `DefaultNArtifactExecutable` : the auto `--reinstall` was configured after `NInstall::addId` (which snapshots the install flags), so it was never forced and the required dependencies of the executed artifact (e.g. `ntexup-engine`, `ntexup-api`, and the libraries reached by `NMutableClassLoader` imports) were redeployed from their stale installed copies
- 2026-11-06 : added `NElements::fromElement(NElement, Type)` and `NElements::convert(Object, Type)` to deserialize generic targets such as `List<MyBean>` (use `new NTypeReference<List<MyBean>>(){}.type()`)
- 2026-11-06 : added `NReflectType::findSuperType(Class)` returning the resolved parametrized view of a super class/interface (e.g. `Map<String,Integer>` for `class Props extends HashMap<String,Integer>`)
- 2026-11-06 : fixed `NReflectType` generics : `superType()`/`interfaces()` of parametrized types, type variables substituted at any depth (nested arguments, arrays, wildcards, owner types), so inherited properties resolve correctly (`Leaf extends Mid<Integer>`, `Mid<X> extends Base<List<X>>`)
- 2026-11-06 : fixed `NReflectType::isAssignableFrom` (parametrized types and wildcards), `toArray` (primitives, nested classes, arrays), `rawType` (no more null for classes), JDK compatible names/equality of synthetic types, NPE in `getDeclaredProperty`/`declaredMethods`, thread safe type cache
- 2026-11-06 : fixed element deserialization of generic types : collection/map subclasses (`class PersonList extends ArrayList<Person>`), raw concrete maps (`TreeMap`), `Deque`/`HashSet`/`BlockingQueue` targets, `Map.Entry` value type, generic arrays (`List<X>[]`), wildcards (`List<? extends X>`), generic records and `Object` targets (no more `NOptional` values)
- 2026-11-06 : added `Iterable` mapping : non `Collection` iterables are serialized as arrays (`NToElement` still honored) and deserialized as collections or through a `List`/`Collection`/`Iterable` constructor
- 2026-11-06 : fixed `NTypeReference` equality (two references to the same type are now equal), JDK compatible parametrized type and `NTypeReference.of(List.class, String.class)` now builds `List<String>`
- 2026-11-05 : added support for record creation
- 2026-11-05 : added NMsgSnapshot
- 2026-10-27 : added NText::ntfText
- 2026-10-26 : fixed DefaultNUncompress issue
- 2026-10-23 : fixed Yaml parsing support
- 2026-10-23 : fixed MTF parsing support issues
- 2026-10-23 : fixed NTF parsing support issues
- 2026-10-20 : The re-exec path now preserves the child process’s exit code and restores the interrupt flag if waiting is interrupted.
- 2026-10-20 : fixed Boot issue when similarity explodes
- 2026-10-18 : added NSystemTerminalBase::interruptHandler
- 2026-10-15 : added better Complex number support
- 2026-10-05 : added cookies support : `NHttpRequest::cookies`
- 2026-09-26 : boot messages about maven demoted to debug (from warnings)
